# Deepdots Popups SDK — Entorno y repos

Memoria del proyecto: configuración de los repos que conforman el ecosistema de popups + surveys de Deepdots. Todos comparten el mismo backend.

## Backend común

| Entorno | Base URL |
|---|---|
| Producción | `https://api.deepdots.com` |
| Desarrollo | `https://api-dev.deepdots.com` |

Autenticación de cliente: `publicKey` (= `apiKey`). Endpoints de popup conocidos: `GET /sdk/popups` (web) y `GET /sdk/{publicKey}/popups` (KMP) para definiciones; `POST /sdk/popups` para eventos de popup `{publicKey, status, popupId, userId}`. El envío de Feedback de survey lo hace el Surveys SDK contra `api(.|-dev.)deepdots.com`.

## Relaciones del ecosistema

```
Popup Web (popup-sdk)  ─┐
                        ├─► @magicfeedback/native (surveys) ─► api(.|-dev.)deepdots.com
Popup Nativo (KMP)     ─┘        (form/send: answers, profile, metrics, metadata, text)
   │                                              ▲
   └─► POST /sdk/popups (estado popup) ───────────┘
```

- Los dos SDKs de popup gestionan **cuándo/cómo mostrar** el popup y reportan su **estado** (`SHOWED/PARTIAL/COMPLETED`) a `/sdk/popups`.
- El **envío de respuestas de survey** (y el modelo de Feedback completo) lo hace el Surveys SDK vía `send()`.
- Identidad hoy: `userId` se pasa pero **no se autogenera ni persiste** en ningún SDK. No existe concepto de `session_id` de navegación.
